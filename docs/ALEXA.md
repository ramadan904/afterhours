# Connecting Afterhours to Alexa+

Everything Alexa+ needs to connect to a deployed Afterhours server, in one place. Replace `https://HOST` with your
deployment's public URL (`PUBLIC_URL`; on AWS, the `McpEndpoint` stack output without `/mcp`).

> Alexa+'s MCP Toolkit isn't open to hackathon participants, so we couldn't walk through the console ourselves. The
> values below come from this server and from Amazon's MCP QuickStart and account-linking pages; the console's field
> names may differ from the ones used here.

## 1. Check the server first

```bash
npm run conformance -- https://HOST
```

Every line should read PASS: RFC 9728 metadata, S256 PKCE, a bare 401, MCP 2025-11-25, annotations and output schemas,
and p95 latency under 500 ms measured from where you run it. Run it from `us-east-1` for the closest match to Alexa.

## 2. MCP server

| Setting | Value |
| --- | --- |
| Server URL | `https://HOST/mcp` |
| Transport | Streamable HTTP (MCP 2025-11-25), stateless, JSON responses |
| Protected resource metadata | `https://HOST/.well-known/oauth-protected-resource` |
| Unauthenticated requests | `401`, no `WWW-Authenticate` header |

## 3. Account linking (OAuth 2.1 authorization code + PKCE)

| Setting | Value |
| --- | --- |
| Authorization URI | `https://HOST/authorize` |
| Access token URI | `https://HOST/token` |
| Client ID | Any value you choose, e.g. `alexa-afterhours`; set the same as `ALEXA_CLIENT_ID` |
| Client secret | On AWS, generated by the stack (`deploy-aws.sh` prints the command to read it). Elsewhere, any long random value set as `ALEXA_CLIENT_SECRET` |
| Client authentication | HTTP Basic (`client_secret_basic`); `client_secret_post` also works |
| Scopes | `market portfolio trade` |
| PKCE | S256 (required; `plain` is refused) |
| Resource | `https://HOST/mcp` (must match exactly) |
| Token lifetime | Access 1 hour; refresh tokens rotate on every use and last 90 days |

Then copy the **redirect URLs** the console shows for account linking into `ALEXA_REDIRECT_URIS` (comma-separated)
and redeploy. Afterhours only redirects to registered URLs, matched exactly.

On AWS: `ALEXA_CLIENT_ID=... ALEXA_REDIRECT_URIS=... ./scripts/deploy-aws.sh`. The client secret lives in Secrets
Manager and never appears in a parameter, a file or the shell history.

## 4. What the person sees when they link

Alexa opens `https://HOST/authorize`. The page offers:

- **Sign in with your wallet:** Phantom, Solflare, Backpack or any Wallet Standard wallet signs a short message
  (free; it can't move funds). This links a verified wallet.
- **Watch an address:** paste any Solana address for read-only use. Trades proposed for it still need that wallet's
  signature on the confirm page.

## 5. Try it

- "Alexa, ask Afterhours what happened overnight."
- "How's Tesla doing?" / "What about Nvidia?"
- "How's my portfolio?"
- "Tell me if Coinbase moves more than 3 percent." / "Tell me if Nvidia goes above 250."
- "Buy 25 dollars of Apple." Alexa reads a code. Open `https://HOST/go`, enter it, and sign.
- "Did my trade go through?"

On a device with a screen, the briefing, stock, portfolio and trade answers also show a card, if Alexa+ renders MCP
Apps `ui://` resources (see FRICTION.md, item 3).
